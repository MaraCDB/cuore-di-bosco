# SEO and GEO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the 15 redesigned pages (IT/EN/DE) findable by search engines and AI assistants: correct JSON-LD, hreflang, sitemap, widened titles/descriptions/keywords, a home FAQ section, Esplora trail links and `llms.txt`.

**Architecture:** Pure head/data work plus one new visible component. B&B JSON-LD stays in `utils/structured-data.ts`; new `utils/seo.ts` computes hreflang/og:locale from the route and is used by `layouts/default.vue`; FAQ text lives once per language in `utils/home-faq.ts`, rendered by `components/HomeFaq.vue` (which also emits the `FAQPage` JSON-LD) on the three home pages. Sitemap and `llms.txt` are static files in `public/`.

**Tech Stack:** Nuxt 3.17, @nuxtjs/i18n (no_prefix), Vitest with `@nuxt/test-utils` (`environment: 'nuxt'`, happy-dom), tests in `tests/*.nuxt.test.ts`.

**Spec:** `docs/superpowers/specs/2026-11-05-seo-geo-design.md` (approved 2026-11-05, commit a0dd051). Read it before any task; Italian copy is copied from it verbatim.

2. Client-side navigation between languages (`/it` → `/en/rules`) must update hreflang, `og:locale` and JSON-LD, not keep the first page's values. → test in Task 2.
3. Text with apostrophes and typographic quotes (’ « ») must produce parseable JSON-LD in every language. → `JSON.parse` assertions in Tasks 1 and 3.
4. Long German questions at 390 px: the open/close marker must stay on the right and the question must wrap, not overflow. → browser check in Task 6 (no unit test can see layout).
5. The FAQ answer text a visitor reads and the `FAQPage` answer an AI reads must be the same words. → equality test in Task 3.
